# 纯需求独立开发与验证试跑

北京时间 2026-11-27 12:34:54 开始。本轮抽取 SpecGuardBench 中 pytest 项目同一个 unescape 函数的 S3、S4 条款做函数级实验。选择依据是单函数、仅依赖标准库，可以独立执行。样本按便利选择，一次生成。原始英文条款见评分材料的 spec 字段。

开发与验证分别在两个新会话中生成，二者都仅收到相同的英文规格及函数签名。开发者编写实现；验证者编写标准库 unittest，两个会话都未使用工具。两份产物写入后按 SHA-256 冻结，随后用相同测试对不同实现评分。本次合并同函数两条条款，用标准库运行，没有执行官方整仓评分，没有对照「生成测试时可见参考实现」的条件；无法排除模型训练时接触过项目。

| 测试对象 | 七个测试方法的结果 |
|---|---|
| AI 独立实现 | 7 个通过 |
| 官方参考函数 | 7 个通过 |

| 官方 S4 违规实现，参数名由 s 改为 string | 7 个通过，漏检。冻结后的独立评分探针确认按 s= 调用时报 TypeError |

补充诊断枚举了反斜杠后跟单个 ASCII 字符的 128 种输入，AI 与官方参考仅在逗号上表现不同。按 S3 明文列举的字符，逗号不在清单内。AI 保留前导反斜杠，官方参考移除它。官方正则把连字符放在加号与点号之间，在该字符类内形成了包含逗号的范围。这是文档与参考行为的歧义/不一致证据；未取得维护者对该边界的解释。AI 验证测试未覆盖这一差异。单个函数不能估计 AI 开发正确率或证明看参考实现会导致验证偏差。

核验入口：sha256sum -c 冻结.sha256，再运行 python 盲评.py。测试日志、128 种输入差异及关键字调用结果保存于[结果](结果.json)。
