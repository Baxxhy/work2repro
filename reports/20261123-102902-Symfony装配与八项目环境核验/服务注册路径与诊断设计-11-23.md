# 服务注册路径
逐一连接任务提示、原始回答、执行行及生成轨迹。10/10 任务在生成时均收到可以提交 repo/behat_services.yml 的明确说明。10/10 执行行均含一个 registered_contexts，均无 rejected_files。7 份回答只交付 PHP；3 份同时交付 YAML，其中两份只指定了部分依赖，另一份引用了不存在的服务。见逐任务证据和变更清单。

锁定引擎 benchmark/r2t/bench/harness.py 的 write_registration 会把生成的上下文注册成 Symfony 服务。类型在容器里有多个实现，或项目只按特定名称登记服务时，构造函数还需要指定具体实现。autowired_services 只记录引擎对显式片段附加的修正，空列表不能推断没有注册。源码检查中，至少八份轨迹出现了 PHP 语法检查命令；一条组合 shell 命令的最终退出码可能来自随后的 grep 或 git。语法检查不会实例化 Symfony 服务。

例子：三个 Sylius 任务的构造函数请求 ApiClientInterface；后台和商店分别需要 admin 或 shop 客户端。两者均实现同一接口。另一个 Sylius 任务已经指定后台客户端，却给响应检查器填了不存在的服务名。

诊断只给十份提交副本增加或修正服务绑定。PHP 文件逐项保留 SHA-256；断言、步骤与接口调用全部保留。另将同一批开发者测试连同原始服务配置序列化为普通候选提交，检验候选与官方 gold 两种入口。剩余三项另在原候选上打开引擎 keep-artifacts，保存未截断 stdout。诊断副本的运行结果不回写正式 Pass@1。
