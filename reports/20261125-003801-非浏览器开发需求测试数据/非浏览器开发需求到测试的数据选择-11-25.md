# 开发功能需求到可执行测试，该选哪些数据

**真实项目新功能首选 Doc2Feat-Bench Verified（ASE 2026），从产品需求直接生成验收测试首选 DevEval 的 Task 4（COLING 2025 主会）。** 想单独研究多次调用能否保持业务状态正确，再加 ClassEval（ICSE 2024）。选型从零开始，依据是输入中谁定义了待开发的功能、参考测试实际从哪里调用软件，以及评测能支撑什么结论。

本次核对 DevEval 的 22 个项目、Doc2Feat Verified 的 114 条任务和 ClassEval 的 100 项类开发规格。三者的统计单位分别是项目、功能变更、类，结果分开报告。核对的是作者固定版本的输入和测试入口，未运行模型或全套基准。开始时间为北京时间 2026-11-25 00:38:01，核验完成于北京时间 2026-11-25 00:52:55。

## 三条实际需求

- **为数值缩放器新增选项。** scikit-learn 要求给 MinMaxScaler 增加 clip 选项，使变换后的新数据可以被限制在指定上下界内。作者提供了两种目标区间的测试。测试可以直接构造超上界和低于下界的值，调用库并检查结果。写成“变换能运行”就会遗漏这条开发需求。[功能 PR 与参考测试](https://github.com/scikit-learn/scikit-learn/pull/17833)
- **为物流程序开发余额充值功能。** 项目 PRD 规定，充值金额为负时输出失败，有效金额到账后输出当前余额。C++ 项目的验收入口编译程序，将 7 组文件送入标准输入，逐组比较标准输出与预期文件。由此能设计“充值后查询余额”和“输入负数后查询余额”的测试。这里的 7 组是整个物流项目的验收用例数。[产品需求](https://github.com/open-compass/DevEval/blob/bb593c1f9c535ff0dde0c9f4807d58c9566c3a6c/benchmark_data/cpp/logistic_system/PRD.md) · [实际验收脚本](https://github.com/open-compass/DevEval/blob/bb593c1f9c535ff0dde0c9f4807d58c9566c3a6c/benchmark_data/cpp/logistic_system/acceptance_tests/test.sh)
- **为酒店类开发部分入住功能。** ClassEval_42 的 Hotel 规格规定，客人实际入住数量少于预订数量时，差额要保留在预订记录里。一次只检查“入住成功”会遗漏这个状态变化。还可检查超过预订数量时拒绝入住。所有操作直接调用 Python 方法。[作者的类规格、参考测试与解](https://github.com/FudanSELab/ClassEval/blob/eaeac44d0d5dcd8a95feec50726d66fedc73a98f/data/ClassEval_data.json)

## 筛选依据

- **Doc2Feat 首批 55 条的项目分布**为 Astropy 17、scikit-learn 16、xarray 15、Pylint 6、pytest 1。选了数据处理、科学计算和命令行工具五个项目，另将其中四条图表、HTML 显示或显示工具相关任务留在首批之外。逐条对照参考测试补丁、文件路径和新增功能的测试标识。55 条是本轮的保守选样。剩余 59 条中还有可用非浏览器方式测试的功能。公开文档随功能 PR 一同更新，可确定由项目开发者描述了预期行为，未据此推定文档早于实现提交。[固定版逐行数据](https://huggingface.co/datasets/Doc2Feat-bench/Doc2Feat-bench_Verified/blob/b162f36089eae2ff9e3501cd2afa00f202ebb7f5/test/data.jsonl)
- **DevEval** 逐项目核对 PRD、repo_config 及所指参考测试代码。移出 listen-now-frontend 和 login-registration 两个前端项目。保留组使用标准输入输出、库调用或无网页交互的进程。项目 PRD 可直接作为开发任务输入。论文基于已有开源仓库整理数据，没有逐个提供原产品团队在编码前签发 PRD 的历史证明。[论文的构造与评测说明](https://aclanthology.org/2025.coling-main.502.pdf)
- **最贴近工业产品需求的论文**仍是 SeGa（ISSTA 2026 经验论文）。作者直接读取企业产品需求文档，针对 Go 方法生成业务测试。4 个工业项目中的 60 个历史缺陷用作评测标签，生成器的需求来源是产品文档。作者公开了脱敏样例和推理组件，完整项目受保密协议约束。[正文及数据声明](https://arxiv.org/html/2604.23509) · [开放材料](https://github.com/chenyangyc/SeGa)
