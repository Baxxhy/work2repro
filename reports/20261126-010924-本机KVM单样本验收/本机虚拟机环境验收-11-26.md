客户机为 bwrap 配置了允许 userns 的命名 AppArmor profile，解决 loopback 初始化失败。加载 nf_tables 模块，将 Docker 客户端二进制归属设为 root，socket 权限设为 0600，Docker 数据目录设为 0700，并收紧数据父目录写权限。虚拟磁盘位于宿主的 /root/lby-docker/req2test-vm。测试使用普通账号、一个 worker 和官方提供的预测。

从宿主登录客户机使用 `ssh -F /root/lby-docker/req2test-vm/ssh-config req2test-kvm`。在客户机中可用新的 run ID 复验。

```bash
source ~/venv/bin/activate
req2test validate --project python-docx --sample 1 --workers 1 --run-id "smoke-$(date +%s)" --docker-host "unix://$XDG_RUNTIME_DIR/docker.sock"
```

范围为一个项目的一条标准答案。其余七个项目、模型生成质量及多 worker 吞吐量尚未在该客户机验证。
