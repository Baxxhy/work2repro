TestSuiteBench 本轮使用规格生成测试模式。测试通过约定的 /workspace/executable 路径调用 CLI，测试文件放在 /workspace/eval。生成阶段准备函数在 with_executable=False 时运行 reference_cleanup_command 并删除 executable，写入文档提示。轨迹元数据核对 {'tsb_records': 165, 'missing': 0, 'images': {'task_cleanroom_codex': 165}, 'spec_only_prompt_records': 165}。这些是配置与轨迹元数据证据，本轮未逐条重放生成或重新检查所有历史容器镜像层。

Req2Test 官方允许 prompt、受限 workspace 和 runtime setup 规定的 binds。workspace 内包含目标接口与部分项目代码，目标函数体隐藏，运行隐藏目标会抛 implementation hidden 错误。官方同时禁止暴露完整项目、未隐藏源码、ground-truth tests、kit/view/data 原目录、旧结果及上游原仓库。本轮读取 agent/req_agent.py，确认它调用锁定 req2test.inference.run_agent，只适配模型运输、medium 及 JSON 日志。该机制与将完整上游源码目录直接挂给 Agent 有不同的输入范围。

判断可比性必须遵守各 Benchmark 的输入协议。官方规定公开的结构和接口属于合法输入，隐藏实现、参考测试和变异答案属于禁止输入。不能将 Req2Test 简写成只有一段自然语言，也不能将它允许的部分源码视图套用到 TestSuiteBench。本轮没有重新执行模型或改变实验结果。
