## 环境与复用入口

客户机配有 8 个 vCPU、24 GiB 内存、160 GiB 虚拟盘。客户机内使用 rootless Docker、overlay2 和 cgroup v2，普通评测用户已获 memory 委派。宿主机的 Docker 服务和 cgroup 配置沿用原有设置。客户机磁盘位于宿主机的 /root/lby-docker/req2test-vm。八个项目的套件、源码视图和运行时均在该客户机安装。

从宿主机运行下列命令。第一条支持重复调用。第二条直接进入客户机，第三条在客户机内复验指定项目。

```bash
/root/lby-docker/req2test-vm/start-vm
ssh -F /root/lby-docker/req2test-vm/ssh-config req2test-kvm
~/req2test-local validate --project python-docx --sample 1 --workers 1 --run-id "manual-$(date +%s)"
```

## 本机处理记录

Coddy 的参考文件复制操作两次触发原 30 秒超时，随后官方引擎隔离 worker。第一次恢复复用了已完成的 8 对，第二次恢复复用了 45 对。客户机入口将该复制步骤上限设为 120 秒，并取官方剩余总预算与该上限的较小值。测试运行预算和评分函数沿用仓库提交 c0d7138f408bb7935d2c82e0fed82884f519b199。最终同一条 Coddy 样本收齐 145 对且全部检出。[失败证据](Coddy基础设施异常.json) · [本机兼容入口](Coddy复制超时兼容入口.py)

e-petitions 和 Sylius 分别切换至 4 和 3 个 worker，以原 run ID 从 16 和 44 条记录续跑。PrestaShop 用 1 个 worker，避免历史第 11 个 worker 名称过长的问题。客户机登录用户使用专用 bubblewrap AppArmor 配置和私有 Docker socket。每个项目的证据目录包含运行时预检、抽样分母、逐变异记录、官方评分和验收 JSON。核验脚本按项目检查样本 ID、变异体唯一性、分母和官方判定。

```bash
python3 核对验收记录.py
```
