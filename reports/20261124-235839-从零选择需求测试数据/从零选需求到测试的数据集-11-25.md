# 从零选需求到测试的数据集

**首选 Req2Test-Bench，第二套选 TestPrism，有真实缺陷检错主张时再加 TestExplora。** 选型假设每套数据都从零开始。目标是根据真实仓库的自然语言需求写出可执行测试，并在生成阶段看不到标准答案的条件下，衡量测试能否拒绝违规行为、接受合法变化。以下数据量、案例和成绩均来自作者公开材料。

## 五套数据的优先级

|顺位|适合用来回答什么|选择依据与边界|
|---|---|---|
|**1　Req2Test-Bench**|**开发者写下的业务需求，能否变成在真实项目里运行的测试？**|开发者原先写下业务前提、操作和预期。作者从 8 个项目恢复了 5,086 条经过执行验证的场景，把使用同一组参考步骤定义的场景分组，每组选一条，得到 **2,051 条评测场景，覆盖 780 个功能**。在 Target-hidden 视图中生成器可查接口与允许的项目上下文，目标实现和参考测试由评测端保留。需求已写成具体场景，适合考察如何落实业务行为。[论文及分组方式](https://arxiv.org/html/2610.36584) · [作者数据和评测入口](https://github.com/code-philia/Req2Test-Bench)|
|**2　TestPrism**|**同一套测试能否放行不同的正确实现，同时找出错误实现？**|300 个评测任务来自 17 个来源，涉及 67 个仓库或项目。生成器可见任务说明和初始程序，评分用的实现全部隐藏。每题有 1 份参考实现、4 份其他通过原评分程序的实现、5 份被判错的实现。官方联合成功还要求测试在初始状态失败。题源含仓库维护、算法和性能优化，需按任务来源报告结果。作者同时公开了可供同预算比较的 TestHelix 方法。[论文及指标](https://arxiv.org/html/2610.12289v2) · [评测代码与数据入口](https://github.com/TestPrism/TestPrism)|
|**3　TestExplora**|**方法能否检出开发者真正修过的错误？**|ICML 2026，2,389 项任务来自 482 个仓库的 1,552 个 PR。选有清楚行为要求和修复的 PR，在同一测试中验证缺陷版失败、修复版通过。官方 F2P 按 PR 计数。其黑盒输入包括签名和自动生成的接口文档，适合作为独立真实缺陷验证。作者内置的 Agent 接口目前支持白盒，采用黑盒 Agent 需说明输入与适配。[正式论文](https://proceedings.mlr.press/v306/liu26ct.html) · [指标](https://arxiv.org/html/2602.10471v2) · [官方实现](https://github.com/microsoft/TestExplora)|
|**4　TestSuiteBench**|**给一份完整软件规格，能否自行规划并交付整套测试？**|165 个开源应用，每个项目一份规格，配有针对具体要求的变异。作者用 Agent 根据已有参考测试所覆盖的行为起草规格，再迭代修订。它重点考察长规格下的场景选择和整套测试的质量。如果论文把“整份规格如何拆成完整套件”设为首要问题，这套应排第一。[规格构造原文](https://arxiv.org/html/2610.13065) · [作者项目页](https://www.sri.inf.ethz.ch/publications/egashira2026testsuitebench)|
|**5　SpecGuardBench**|**有参考实现可看时，生成的断言会不会把某种实现习惯误当成需求？**|13 个 Python 仓库、30 个功能、291 条规格，精简集 100 条。每条都有违规实现和至少一个仍满足该条要求的替代实现，适合单条规则的精细诊断。官方生成阶段展示参考实现，所以它回答的科学问题与 TestPrism 的隐藏候选实验不同。[论文和设置](https://arxiv.org/html/2610.16870v1) · [作者数据卡](https://huggingface.co/datasets/coxhin/SpecGuardBench)|

## 为什么第二套选 TestPrism

论文中联合成功率最高的基线，在相同 300 题上，只要求初始程序失败、单一参考实现通过时，成功率为 **59.67%（179/300）**。继续要求所有合规候选通过、所有违规候选失败时，降到 **28.00%（84/300）**。同一批生成测试有 95 题通过了前一种判定，却在新增候选上暴露局限。这个差距给“需求约束有没有完整写进测试”提供了可直接比较的指标。合规标签由原题评分程序确定，其覆盖范围亦是结论的边界。[作者表 2 和评分定义](https://arxiv.org/html/2610.12289v2)

公开任务中的 Matplotlib 示例要求颠倒坐标上下限时，线性轴和对数轴都要反转。仅检查线性轴会遗漏对数轴上的回归。另一个任务要求按普通投球、补中和全中的规则计算保龄球得分。逐项读取这两条的指令和评分清单，都可核到 5 个合规标签和 5 个违规标签。前一条来自仓库缺陷描述，后一条来自编程练习。仓库需求泛化应单独看对应任务。[Matplotlib 原题](https://huggingface.co/datasets/testprism-anonymous/testprism-verified-tasks/blob/ac3578d6deb120f34fd1d545dbe8429c547a8a62/verified_tasks/test/from-swe-bench/matplotlib__matplotlib-14623/task.yaml) · [两条样本及清单哈希](公开清单核验-11-25.json)

Req2Test 同样要保留项目分布。8 个项目的 Eval 数量为 Coddy 274、Algorand SDK 111、Kapua 330、CoreShop 334、PrestaShop 348、Sylius 319、python-docx 237、e-petitions 98。三个 PHP 项目合计 1,001/2,051（48.81%）。因此适合沿用逐项目及官方等权统计，另列通过执行之后的检错情况。[作者表 3](https://arxiv.org/html/2610.36584) · [计数核查](公开清单核验-11-25.json)

## 邻近选项

WebTestPilot 的 100 个网页场景适合研究浏览器里的用户可见错误。Sakura 从复杂 Java 测试反推文字描述，适合编译、测试结构和覆盖方面的方法对照。11 月更新的单元测试生成与转译研究直接从代码生成或迁移测试。当前首选组合覆盖的则是开发者需求、隐藏候选的判定质量和真实修复这三种证据。[WebTestPilot](https://github.com/code-philia/WebTestPilot-benchmark) · [Sakura](https://conf.researchr.org/details/issta-2026/issta-2026-research-papers/21/Sakura-An-Approach-for-Generating-Complex-Tests-from-Natural-Language-Test-Descripti) · [11 月单元测试研究](https://arxiv.org/abs/2611.21797)
