# 相关论文怎样组织痛点

本轮核对三篇论文的摘要和引言。以下只借鉴问题组织及可区分的证据维度，不据此宣称本研究已有新方法或新颖性。

## TELPA，TOSEM 2025

论文 Advancing Code Coverage: Incorporating Program Analysis with Large Language Models 从难覆盖分支出发，明确两类困难。复杂对象依赖特定的构造顺序，分支条件还依赖其他过程的语义。然后分别对应对象构造分析和分支依赖分析，辅以反例反馈。

它的组织方式是从同一个覆盖目标中找出不同技术障碍，每项均能对应具体代码和实验。我们的业务状态映射与其对象构造有重叠，后续需要比较需求场景、受限接口视图和跨业务观察位置是否带来额外问题。当前尚无TELPA在本次两个Benchmark上的对照结果。

来源 https://arxiv.org/html/2404.04966 ，正式DOI为10.1145/3748505。期刊版和早期预印本结果有差别，本轮不复述其数值提升。

## TOGLL，ICSE 2025

论文 Correct and Strong Test Oracle Generation with LLMs 将oracle的正确性、强度和多样性分开研究。正确性要求避免误报，强度要求发现错误行为。两者使用不同证据评价。

可借鉴的是把抽象的“断言不好”改成可检验的问题，明确断言接受了哪些违反预期的结果。我们的对应关系丢失属于强度问题的一种具体表现，尚需证明在自然语言需求与真实业务场景下哪些条件超出了已有工作的处理范围。

来源 https://arxiv.org/html/2405.03786 ，正式DOI为10.1109/ICSE55347.2025.00098。

## MuMuTestUp，2026年预印本

论文从三种现有能力缺口组织动机。可执行性不足以保证断言充分，粗粒度行覆盖不能提供具体分支指导，精确匹配检索难以处理模型给出的不存在符号。三项分别落到断言、覆盖反馈和检索机制，并用组件消融验证。

可借鉴的是每个痛点有明确机制与检验条件。我们的新一轮痛点也需分别落实到遗漏条款、错误业务路径、约束变弱。作者的隐藏变异反馈不能直接用于本次Agent生成，否则会改变实验协议；本轮仅用生成后评测材料解释缺口。

来源 https://arxiv.org/html/2605.19265v1 。页面带有未替换模板会议字段，按预印本记录其状态。

## 本次应采用的组织

中心问题为用户需求在生成测试中的落实。三个候选挑战为需求条款对应、业务语义映射、断言约束保持。

每项应依次提供真实需求、轨迹中的信息访问与选择、最终代码、执行影响、反例和所需补充证据。相同错误可多标签，先报告交集，再谈机制。

现有5个深度案例足以定位可调查的问题，尚不足以给出三个根因的全量比例。最终是否保留三项，取决于进一步标注后能否分别解释失败、找到独立成功对照，并与现有技术区分。
