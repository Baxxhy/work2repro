# Req2Test 生成中断与配置复核

2026-11-18 北京时间。对照锁定的作者代码、论文第 4.2 至 4.3 节和现场保存的历史生成记录。当前基线提交的 2,051 条预测和报告是审计输入。

## 已确认的缺陷

现有正式结果至少有 50 条被误记为无测试产物的生成失败，另有 3 条历史退出未定位。

|类型|确认数|证据|
|---|---:|---|
|请求限流中断|41|父轮网关实际收到 HTTP 429。CLI 最终错误为 `exceeded retry limit, last status: 429 Too Many Requests`，每条都有 turn.failed、没有 turn.completed，1 至 25 次代理请求后退出。追踪目录与当前使用的预测匹配，均未生成文件。|
|线程启动失败|6|源作业日志有 Python `can't start new thread`，发生在生成运行器或其转发线程。|
|任务视图读取失败|3|源作业日志有官方 ViewError，打开 CoreShop 或 e-petitions 的 base.tar.zst 时读到空文件。该证据对应历史生成时点。|
|原因未确定|3|本地作业退出 255，日志为空，没有工作区轨迹。|

429 的路径可在父轮控制器及 generation_outcome.py 交叉核对。网关状态保存了 HTTP 429，通用限流响应不符合控制器专门处理的认证与额度错误文本。生成分类依赖重连等网络错误关键字，CLI 的最终 429 文本未命中，落入 official_agent_nonzero_exit。旧任务复用清单中的 9 个异常也被归为同一标签，历史空预测随之进入全量。官方生成协议要求补跑被服务侧限制或 benchmark 环境中断的生成，统计前应区分它们与正常终止后没有交付测试的任务。[作者生成协议](https://github.com/code-philia/Req2Test-Bench/blob/c0d7138f408bb7935d2c82e0fed82884f519b199/docs/agents.md) · [论文第 4.3 节](https://arxiv.org/html/2610.36584#S4.SS3)

## 分数影响

按现有 8 项目等权口径，暂时排除已证实的 50 条用于诊断，Pass@1 为 30.25%。即使 50 条恢复后全通过，均值也只到 32.02%。连 3 条尚未定位的旧结果也假设全部通过，上界 32.23%。这三组数字都是反事实计算，当前发布值仍为 29.73%。按作者要求做可比修复，应以生成中断为重跑条件，并逐任务复用已经有效的产物。

## 已核实的配置差异

|项目|作者论文 Luna|现有队列|
|---|---|---|
|推理等级|high|medium。1,175 条直接匹配最终预测输出路径的作业均有相同的实际请求字段。|
|Codex CLI|0.153.4|保存版本 0.160.0，经过本地登录网关转发。|
|生成环境|paper 档未加载应用运行包|使用当前官方生成器的 runtime pack，正式评测在完整实现上跑。|
|请求数与生成时限|最多 200 次、3,600 秒|上述 1,175 条匹配作业均为 3,600 秒，平均 12.79 次、最大 34 次，1134 条退出 0、41 条非零。7200 秒为后续控制器配置，不是这些预测的原始预算。|

论文表 5 中，作者 Luna 平均请求次数 23.6。我们直接匹配的 1,175 条大致 12.79 次，样本构成与运行条件并未控制。实际请求字段确认了客户端提交的 model 和 effort。配置日志不能据此推断服务端内部有效算力。也不能把请求次数差归因到单一设置。[论文第 4 节及表 5](https://arxiv.org/html/2610.36584) · [作者榜单中 paper 运行包脚注](https://github.com/code-philia/Req2Test-Bench/blob/c0d7138f408bb7935d2c82e0fed82884f519b199/results/leaderboard.md)

50 条误计说明当前复现存在可修复偏差，同时最多只解释 2.30 个百分点。上一轮核实的真实框架集成症状仍是大头，例如 CoreShop/Sylius 的测试服务注入错误、Kapua 的测试编译错误、PrestaShop 步骤绑定缺失。要进一步判定谁的问题，需先固定一组相同任务，比较论文配置与本配置，并使用同一个评测器检查生成产物。公开项目汇总没有给出逐任务可比的失败原因，不能据此说 high 单独造成了差距。
